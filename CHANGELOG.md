# Changelog

All notable changes to this package are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the package uses [Semantic Versioning](https://semver.org/).

## [0.1.0] - 2026-10-08

First release. Requires Unity 6000.0 or newer, UniTask and `com.unity.ugui`.

### Added

- **Root and layers.** `ViewRoot` sits on a canvas that the project owns and builds the layers, the input shield and the navigator under it. Three layers are built in: `screens` (a history stack that takes back), `popups` (modal, with a shared backdrop, closed by navigation) and `system` (modal blocking overlays). A project adds layers of its own with `ViewLayer` and `ViewLayerRules`. The menu `GameObject > UI > UIDirector Root` creates a root with a `BackInput` and an `EventSystem`; a camera variant creates a root with its own UI camera. `ViewRootSetup` initializes a root from code with an inject delegate, an asset provider, extra layers and an error handler. The root supports overlay and camera canvases, a persistent root across scenes, a numbered sorting band with a refusal instead of a wrap, a load indicator, load and transition timeouts, a waiting cap, `SafeAreaFitter` and the Prefab Mode UI environment.
- **Catalogs and keys.** `ViewCatalog` assets hold `ViewEntry` rows: an id, a prefab or an asset key, a layer, a retention, a back policy, a cover policy, a covered mode, close on backdrop and allow multiple. `ViewKey<TArgs, TResult>` names a row with its argument and result types, and a static class marked `[ViewKeys]` is checked against the catalogs by the editor. Catalogs are added to and removed from a running root through `INavigator.AddCatalog`, which takes an owner.
- **Opening and results.** `Open` returns a `ViewHandle` at once; `ShowAsync` completes with a `ViewResult<TResult>` in every case. A refusal, a failed load, a close by back or backdrop, an owner that ended and a destroyed root are data in the result (`CloseReason`, `RejectReason`, `HasValue`, `Value`), never exceptions. `OpenOptions` carries a source tag, `RejectWhenBusy` and a reserved request id. `ViewHandle.Close`, `WaitForCloseAsync`, `CloseAll` and the queries `IsOpen`, `TryGetOpen` and `TryGetTop` cover the rest of a view's life.
- **Owners.** Every open and every registration (`HoldInput`, `AddObserver`, `AddCatalog`, `PreloadAsync`) takes a required `CancellationToken` as its owner. When it ends, the view or registration ends. `INavigator.RootToken` is the explicit "as long as the UI exists" owner.
- **Navigation and back.** Screens stack on a history layer; opening an id that is already in the stack returns to it, and `CloseTo` pops everything above a screen. `Back()` is the single back rule and returns `false` when nothing handled the press. `BackPolicy` sets per row what back does, including `HandledByView`, which asks the view. `BackInput` turns the Escape key into `Back()` and raises `Unhandled`; with the Input System it reads Escape on any keyboard through an input action it owns, and it does nothing until its root is initialised. `ViewButton` gives buttons the actions Back, CloseView and OpenView without code.
- **Popups, overlays and input.** A shared backdrop under the top modal view, optional close on a backdrop tap, and an input shield that is counted and goes up in the same call that accepts a request. While it is up, back closes nothing but still withdraws the newest request that is waiting or loading. `HoldInput` blocks input from code. System overlays block input while they run. To hide the whole UI for a moment, the documentation gives a recipe: a `CanvasGroup` on the root with alpha 0 and `interactable` off, plus `HoldInput`.
- **View authoring.** `ViewBehaviour`, `ViewBehaviour<TArgs>` and `ViewBehaviour<TArgs, TResult>` are optional sugar over `IView<TArgs, TResult>`, `IViewVisible` and `IViewBack`. A view receives hooks that only begin things. Work that has to end is registered on a `ViewScope` (an open scope, and a visible scope for each span on screen) that the package ends on every path: `Bind` for a `UnityEvent`, `Subscribe` for any other event, `Add` for a disposable, `OnEnd` and `Run`. A view can `Decline` an open and `Complete` with a result. A catalog row can keep one idle instance per id, released by `Trim` and on `Application.lowMemory`.
- **Transitions.** `FadeTransition`, `ScaleTransition` and `SlideTransition` run on unscaled time, with a transition timeout and a synchronous `Snap`. One frame advances a built-in transition by at most 1/30 s, so below 30 fps it takes longer than its duration. `ViewTransition` is the base for transitions of your own and its contract is documented.
- **Queue.** `ViewQueue` presents requests one at a time by priority on one layer, above the navigator and through `INavigator` only. The constructor throws `ArgumentException` for a layer the root's navigator does not have. `IViewGate` allows or denies an item at enqueue and before presentation. Holds pause the queue, are counted and record the member and line that took them. Owners end waiting items. The queue hands the navigator one request at a time, so the navigator's waiting cap is never reached, and `EnqueueAsync` completes with the outcome also when an item never shows, including when the presentation itself fails. A queue ends when its lifetime ends or when its navigator's root is destroyed: waiting items end as not shown with `RejectReason.Cancelled` or `RejectReason.RootGone`, later calls are inert, and neither token keeps the queue alive. An item whose catalog row is on another layer than the queue's ends as not shown with `RejectReason.WrongLayer`. A feature can add its own catalog at run time with an owner.
- **Events and diagnostics.** `IViewObserver` receives `Enqueued`, `Requested`, `Shown`, `Closed`, `NotShown` and `Settled` events, in a documented order and without view arguments. `ViewErrorHandler` receives exceptions thrown by your own code. Problems carry stable ids `UIDIRECTOR101` to `UIDIRECTOR126`, each with a section in the Troubleshooting page: 101 to 120 and 126 at run time in the editor and development builds, 121 to 124 from the catalog validator, and 125 (a row with an empty id) from the validator and at run time when a catalog is registered. A view lost outside the package (destroyed or deactivated by other code) ends its request with `UIDIRECTOR107`; a kept instance lost that way is released, and the next open creates a new one. A text read-out is available through `INavigator.Describe`.
- **Editor tools.** `Window > UIDirector` shows the layers, requests, phases, shield holders and newest events live in Play Mode. `Tools/UIDirector/Validate Catalogs` checks every catalog in the project, from the menu, the catalog's Inspector and a batch entry point for a build pipeline. `Tools/UIDirector/Documentation` opens the documentation of the installed version, and the window and the catalog Inspector link each diagnostic to its Troubleshooting section.
- **Threading and cost.** Opening, registering and queueing throw on another thread; `ViewRegistration.Remove`, `CloseAll`, `Trim` and `ViewQueue.Clear` are posted to the main thread. An idle root, the queries, event dispatch and a running fade allocate nothing.
- **Addressables integration.** `AddressablesViewProvider` loads views by asset key and compiles when `com.unity.addressables` is installed. It supports preload leases through `PreloadAsync`, keeping and trimming, and the root's load timeout; the catalog validator warns about asset keys that match no address ([UIDIRECTOR124](Documentation~/Troubleshooting.md#uidirector124)).
- **DOTween integration.** `TweenTransition` is a transition configured in the Inspector, with a documented kill-safe pattern and a sample transition (`PunchTransition`) for writing your own on DOTween. It compiles when DOTween is present, and the menu `Tools/UIDirector/DOTween Integration` turns it on when only the DOTween assembly is in the project.
- **Zenject integration.** `NavigatorInstaller` binds the navigator and the root in a container, and the container injects every view instance the root creates. It compiles for Extenject 9.0.0 or newer as a package, and for Zenject under `Assets/` after `Tools/UIDirector/Zenject Integration`.
- **Samples.** Basic Usage, Queue Usage, Addressables Usage, DOTween Usage and Zenject Usage, each with a README, a scene and prefabs.
- **Documentation.** A README with a five-minute start, one guide per task, an API reference, a Troubleshooting page with one section per diagnostic id, design notes with five decision records, `llms.txt` and `llms-full.txt` for AI tools.
